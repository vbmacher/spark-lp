= How spark-lp solves a model
:toc: left
:source-highlighter: highlightjs

See link:usage.adoc[the usage guide] for the DSL, result ownership, progress callbacks and
cooperative stopping.

== Compile to equality form

The linear solver minimizes `c^T x` subject to `A x = b`, `x >= 0`. Continuous convex QP adds a
quadratic objective; diagonal curvature and sparse coupled factors are handled as described below.
The compiler stores columns of `A` as sparse rows of `AT = A^T`; variable order is
`(declaration order, encoded key)` and row order follows constraint declaration and group keys,
with no wide pivot.

[mermaid]
----
flowchart LR
  M[Model and Spark sources] --> V[Validate keys and coefficients]
  V --> P[Fold fixed variables and shift bounds]
  P --> E[Check empty rows and exact duplicate equalities]
  E --> A[Add inequality and upper-bound slacks]
  A --> C[Build aligned sparse AT and cost blocks]
  C --> L[Continuous LP or integer search]
  L --> R[Undo transformations and report diagnostics]
----

[cols="1,2",options="header"]
|===
|User model |Solver representation
|`x >= l` |`x = l + y`, `y >= 0`; subtract `a*l` from RHS, add `c*l` to the objective constant.
|`x <= u`, finite `l` |Add `y + slack = u - l`.
|`x = l = u` |Remove the variable and substitute its value.
|Free `x` |`x = positive - negative`, both nonnegative.
|`a*x <= b` / `>= b` |Add `+slack` / `-slack` for equality.
|Maximize |Negate costs; restore sign and constant afterward.
|===

Example: minimize `2*x + 7` with `5 <= x <= 10` becomes minimize `2*y + 17` with `y + slack = 5`;
`y = 0` reconstructs `x = 5`, cost `17`. Duplicate detection hashes candidates, then compares
normalized coefficients before merging — distinct rows are never merged on a hash collision alone.

== Predictor-corrector interior point

`x` is the primal vector, `lambda` the equality multiplier, `s` the nonnegative dual slack.
Initialization solves two unweighted normal systems, then shifts `x` and `s` strictly positive
(including zero-cost / zero-complementarity starts).

[mermaid]
----
flowchart TD
  I[Initialize positive x and s] --> R[Compute primal and dual residuals]
  R --> W[Update mu and diagonal weights]
  W --> P[Solve affine predictor]
  P --> C[Choose centering and solve corrector]
  C --> U[Step while keeping x and s positive]
  U --> T{Residuals below tolerance?}
  T -->|Yes| O[Optimal]
  T -->|No| F{Infeasibility certificate?}
  F -->|Yes| S[Report certificate status]
  F -->|No| B{Iteration budget left?}
  B -->|Yes| R
  B -->|No| L[IterationLimit]
----

Each iteration sets `mu = x^T s / n` and `D2 = diag(x/s)` with guarded inverses; both Newton
directions solve `A D2 A^T deltaLambda = rhs`. The affine predictor sets
`sigma = min(1, (muAffine/mu)^3)`; the corrector adds centering and a second-order correction, and
the step uses `etaIteration` to stay inside the nonnegative cone. This follows the
predictor/corrector formulation in
https://link.springer.com/article/10.1007/s10589-019-00103-y[Cui et al., section 2.1].

Convergence requires all three normalized residuals below `SolveConfig.tolerance`:

....
primal = ||A*x - b||_2 / (1 + ||b||_2)
dual   = ||A^T*lambda + s - c||_2 / (1 + ||c||_2)
gap    = |c^T*x - b^T*lambda| / (1 + |b^T*lambda|)
....

Infeasibility tests `y = lambda/(b^T lambda)` when the denominator is positive:
`A^T y <= infeasibilityTolerance`, `b^T y = 1`. Dual infeasibility tests `z = x/|c^T x|` when
`c^T x < 0`: `||A z||_inf <= infeasibilityTolerance`, `c^T z = -1`, `z >= 0` — unboundedness only when
a primal-feasible point is also known. These are floating-point certificate tests; a numerical
failure retries them on the last completed iterate before raising.

== Newton solver: Cholesky, CG, Auto

[cols="1,2,2",options="header"]
|===
|Strategy |Computation |Driver cost
|`Cholesky` |Aggregate the weighted Gramian and factor its contiguous independent blocks; reuse for both directions. |`O(m^2)` storage; factorization `O(sum(block^3))`, worst case `O(m^3)`.
|`ConjugateGradient` |Apply `v -> A*(W*(A^T*v))+Rd*v` in Spark with a bounded partial-Cholesky preconditioner. |`O(m)` vectors plus `O(m*rank)` preconditioner storage.
|`Auto` |Cholesky through 10000 equality-form rows (or a lower `maxLocalConstraints` cap); CG above it. |Follows the selected strategy.
|===

The 10000-row cutoff is an unmeasured heuristic to limit long CG sequences on medium models; the
link:../benchmarks/src/results/TODO.md[pending benchmark campaign] will evaluate it.
`maxLocalConstraints` (default 10000) is a separate resource cap: lowering it can switch Auto
earlier; raising it does not raise the cutoff. To use Cholesky above 10000 rows, select it explicitly
and raise that cap.

Here `m` counts emitted user constraints and upper-bound rows; `n` counts split variables and slacks.
Allow roughly `16*m*m` bytes for Gramian allocations (about 1.6 GB at `m = 10000`), plus ~400 MB
executor aggregation buffers. Explicit Cholesky rejects models above `maxLocalConstraints` and caps
packed arrays at 65535 rows. CG avoids the Gramian limit, but row metadata, RHS, residuals and group
keys stay on the driver and matrix indices are `Int`. The matrix-free operator streams each stored
row once per application (dot product, weight, accumulate into a partition sum); initialization applies
a scalar uniform weight.

== Matrix-free CG equations and regularization

`A` is the original constraint matrix (the code stores `AT`). Let `rb = A*x-b`, `rc = A^T*y+s-c`, and
`q` the complementarity right-hand side. The CG backend uses primal/dual proximal regularization
following https://webhomes.maths.ed.ac.uk/~jgondzio/reports/mtxFree.pdf[Gondzio, sections 3–6]; both
proximal reference points reset to the current iterate, so `rb`/`rc` are original-LP residuals with no
fixed offsets.

[source,text]
----
A*dx + Rd*dy = -rb
A^T*dy + ds - Rp*dx = -rc
S*dx + X*ds = q

W = (S/X + Rp)^(-1)
h = rc + q/x
(A*W*A^T + Rd)*dy = -rb - A*W*h
dx = W*(A^T*dy + h)
ds = -rc - A^T*dy + Rp*dx
----

The affine predictor uses `q = -x*s`; the corrector uses `q = -x*s-dxAff*dsAff+sigma*mu`; both share
the operator and preconditioner. Initialization uses `W0 = I/(1+Rp)`, `G0 = A*W0*A^T+Rd`,
`xTilde = W0*A^T*G0^(-1)*b`, `yTilde = G0^(-1)*A*W0*c`, then strictly positive shifts. Cholesky is the
unregularized reference with an inverse-slack cap; its exact zero-separated blocks are factored
independently by the same LAPACK routine (no coupling dropped by tolerance). See
link:../benchmarks/src/results/REPORT.md[benchmark results] for measured times and memory.

`CgConfig` defaults `Rp = 1e-8` and `Rd = 1e-8` (entries, not square roots), positive throughout a
solve. Larger values improve conditioning but need more outer iterations; very small values lose their
effect to roundoff — scale the LP before using extreme coefficients. CG weights are `1/(s/x+Rp)` with
no inverse-slack cap; nonpositive, nonfinite or underflowed weights fail explicitly. CG's regularized
operator supports dependent feasible equality rows; the direct backend requires full row rank.

The driver-local `org.apache.spark.wrappers.ConjugateGradient` wrapper owns the PCG iteration,
warm-start state, restarts and true-residual replacement, using netlib BLAS (`ddot`, `dnrm2`,
`dscal`, `daxpy`). `CgFactory` supplies the distributed operator and partial-Cholesky preconditioner
and retains rank escalation, monitoring and the bounded-inexact acceptance policy. Retrying with a
stronger preconditioner preserves the current solution and cumulative counts without forming a Gramian.

== Preconditioner and inexact solves

The adaptive preconditioner starts as the regularized diagonal (Jacobi). If an inner solve misses its
tolerance it builds up to 50 partial-Cholesky columns, then doubles the rank on further failures.
Within one weighted system, escalation extends existing factors and the Schur diagonal, fetching only
new columns; later outer iterations inherit the rank but rebuild factors for changed weights. Each
pivot is the largest updated Schur-complement diagonal (ties by row index); only that column is fetched
before the next pivot, and the remaining Schur block is approximated by its diagonal — no full Gramian
is collected.

A pivot at or below `max(Rd, 64*ulp(max(diag(G))))` stops factorization; the preconditioner diagonal
is floored there, and nonfinite values or a Schur diagonal below its negative fail numerically. This
guard affects the preconditioner only — there is no hidden ridge retry after the Newton RHS is built.

The factor budget defaults to 256 MiB (~`32*m*rank` bytes); a driver work cap also limits rank via
`m*rank^2 <= 2e10`. Explicit `preconditionerRank` is clipped to both; rank 0 selects adaptive behavior,
a zero byte budget forces Jacobi. Sequential pivoting costs one distributed column pass per pivot, so
starting from Jacobi avoids paying for pivots on easy systems.

`cgTolerance` (default `1e-10`) and `cgMaxIterations` control the inner solve; its requested residual
is `max(cgTolerance*norm(rhs), 0.1*tolerance*(1+norm(b)))` (initialization uses only the relative
term). Warm starts reuse the predictor solution for the corrector. After exhausting rank and step
budgets, a finite true residual no larger than `max(target, 1e-3*norm(rhs))` may be returned as an
inexact direction; a larger defect, nonfinite residual or nonpositive curvature raises a numerical
failure unless an original-LP certificate holds on the last completed iterate. The outer primal, dual
and gap residuals are always recomputed from the original LP, so solving only the regularized equations
cannot yield `Optimal`. The implementation uses Mehrotra predictor-corrector steps instead of the
paper's fixed barrier reduction, uniform configurable regularization instead of dynamically adjusting
individual diagonal entries, and Jacobi before partial Cholesky. Continuous convex quadratic objectives
extend these equations below; nonconvex, mixed-integer quadratic and quadratically constrained models
are unsupported.

[source,scala]
----
import com.github.vbmacher.spark_lp.newton.CgConfig

val config = SolveConfig(
  newtonSolver = NewtonSolver.ConjugateGradient,
  cgTolerance = 1e-10,
  cgMaxIterations = 1000,
  cgConfig = CgConfig(
    primalRegularization = 1e-8,
    dualRegularization = 1e-8,
    preconditionerRank = 50,
    preconditionerMemoryBytes = 128L * 1024 * 1024))
----

`CgConfig` configures the matrix-free backend only; Cholesky is the direct alternative selected through
`newtonSolver` and ignores CG tuning. Pass `CgConfig` through the `cgConfig` argument. Import core solver choices from
`com.github.vbmacher.spark_lp.newton`; the DSL re-exports `NewtonSolver` through its wildcard import.

== Convex quadratic extension

For `0.5*x^T Q*x + c^T*x`, diagonal `Q` changes the Newton weights to
`W = (S/X + Q + Rp)^(-1)` and direction recovery includes `Q*dx`.
Stationarity uses `A^T*lambda + s - c - Q*x`; the objective gap compares
`0.5*x^T Q*x + c^T*x` with `b^T*lambda - 0.5*x^T Q*x`.
Recession certificates additionally require `Q*d = 0` within tolerance.
Bound shifts preserve both the induced linear term and objective constant.

Sparse coupled objectives use PSD factors `sum(w*(a^T*x+t)^2)`.
Each factor adds nonnegative `u,v`, an equality `a^T*x+t = u-v`, and diagonal
penalty `w*(u^2+v^2)`. Minimizing over `u,v` recovers the exact original penalty.
The solver therefore applies the distributed weighted normal operator to
an enlarged sparse matrix, without collecting a dense Hessian or forming its inverse.
Rows include factor equalities; columns include their two auxiliary variables.

Free-variable splits can make coupled Cholesky systems numerically singular near
convergence. `Auto` selects regularized CG for coupled models containing free
variables; explicit Cholesky is rejected. Separable objectives reject curved free
variables. See link:quadratic-programming.md[representations and restrictions] and
link:../benchmarks/quadratic/README.md[the measured strategy comparison].

Public evidence retains original unshifted costs and curvature. For coupled QP,
the equivalent factor-expanded model is exposed explicitly; see
link:certificates.md[independent certificate verification].

== Opt-in progress policy

When stagnation detection is enabled, `StagnationConfig` adds separate outer and inner progress
windows (defaults: 10 outer iterations patience, absolute improvement `1e-10` plus relative `1e-3`, 100
inner steps patience, 2000-step inner cap). Outer progress compares original-model violation and the
primal/dual/gap residuals before a feasible candidate appears, then objective improvement or improving
residuals after; each component uses `absoluteImprovement + relativeImprovement * abs(best)`. Inner
progress compares `norm(rhs-G*dy)/norm(rhs)` on true residuals across restarts and rank changes for one
right-hand side. A stalled or capped inner solve requests `NoProgress` and discards its unfinished direction.
With controls disabled, inner solves use the per-rank numerical recovery and inexact-acceptance policy.

See link:usage.adoc#_progress_and_cooperative_stopping_continuous_models[progress usage] for
callbacks, metric groups, cancellation and candidate ownership.

== Integer and binary models

Compile once. Branch-and-bound reuses `AT` and `c`; tighter integer bounds change the RHS and objective
offset. Integer bounds and column coefficients stay on the driver.

[mermaid]
----
flowchart TD
  Q[Take node with smallest lower bound] --> B{Bound prunes node?}
  B -->|Yes| N[Next node]
  B -->|No| L[Solve LP relaxation]
  L --> I{Feasible integral point?}
  I -->|Yes| C[Check rounding and update incumbent]
  I -->|No| F[Branch on fractional variable or split interval]
  C --> N
  F --> N
  N --> E{Queue empty or node limit?}
  E -->|No| Q
  E -->|Yes| R[Report incumbent and search status]
----

For minimization, the relaxation's dual objective is the node lower bound and its primal objective a
candidate upper bound. Discard a branch with contradictory row bounds or an infeasibility certificate. A
fractional value `v` splits into `x <= floor(v)` and `x >= floor(v)+1`; near-integer candidates are
rounded only after checking the constraint residual, and the objective includes the rounding change.

Example: maximize integer `x+y` with `2*x+2*y <= 3`. The relaxation reaches `1.5`; branching finds the
integer optimum `1`. Exhausting the search proves optimality within `mip.gapTolerance`; unresolved
branches or `mip.maxNodes` exhaustion give `IterationLimit`. Defaults: 1000 LP nodes, integrality
tolerance `1e-6`, relative gap tolerance `1e-9`. Search is sequential on the driver and can grow
exponentially.
