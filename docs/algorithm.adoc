= How spark-lp solves a model
:toc: left
:source-highlighter: highlightjs

See link:usage.adoc[the usage guide] for the DSL, result ownership, progress callbacks and
cooperative stopping.

The linear solver minimizes `c^T x` subject to `A x = b`, `x >= 0`; continuous convex QP adds a
quadratic objective. The compiler stores columns of `A` as sparse rows of `AT = A^T`, with variable
order `(declaration order, encoded key)` and row order following constraint declaration and group
keys.

== Compile to equality form

[mermaid]
----
flowchart LR
  M[Model and Spark sources] --> V[Validate keys and coefficients]
  V --> P[Fold fixed variables and shift bounds]
  P --> E[Check empty rows and exact duplicate equalities]
  E --> A[Add inequality and upper-bound slacks]
  A --> C[Build aligned sparse AT and cost blocks]
  C --> L[Continuous LP or integer search]
  L --> R[Undo transformations and report diagnostics]
----

[cols="1,2",options="header"]
|===
|User model |Solver representation
|`x >= l` |`x = l + y`, `y >= 0`; subtract `a*l` from RHS, add `c*l` to the objective constant.
|`x <= u`, finite `l` |Add `y + slack = u - l`.
|`x = l = u` |Remove the variable and substitute its value.
|Free `x` |`x = positive - negative`, both nonnegative.
|`a*x <= b` / `>= b` |Add `+slack` / `-slack` for equality.
|Maximize |Negate costs; restore sign and constant afterward.
|===

Example: minimize `2*x + 7` with `5 <= x <= 10` becomes minimize `2*y + 17` with `y + slack = 5`;
`y = 0` reconstructs `x = 5`, cost `17`. Duplicate detection hashes candidates, then compares
normalized coefficients before merging, so distinct rows are never merged on a hash collision alone.

== Predictor-corrector interior point

`x` is the primal vector, `lambda` the equality multiplier, `s` the nonnegative dual slack.
Initialization solves two unweighted normal systems, then shifts `x` and `s` strictly positive
(including zero-cost or zero-complementarity starts).

[mermaid]
----
flowchart TD
  I[Initialize positive x and s] --> R[Compute primal and dual residuals]
  R --> W[Update mu and diagonal weights]
  W --> P[Solve affine predictor]
  P --> C[Choose centering and solve corrector]
  C --> U[Step while keeping x and s positive]
  U --> T{Residuals below tolerance?}
  T -->|Yes| O[Optimal]
  T -->|No| F{Infeasibility certificate?}
  F -->|Yes| S[Report certificate status]
  F -->|No| B{Iteration budget left?}
  B -->|Yes| R
  B -->|No| L[IterationLimit]
----

Each iteration sets `mu = x^T s / n` and `D2 = diag(x/s)` with guarded inverses; both Newton
directions solve `A D2 A^T deltaLambda = rhs`. The affine predictor sets
`sigma = min(1, (muAffine/mu)^3)`; the corrector adds centering and a second-order correction, and
the step uses `etaIteration` to stay inside the nonnegative cone. This follows the
predictor/corrector formulation in
https://link.springer.com/article/10.1007/s10589-019-00103-y[Cui et al., section 2.1].

Convergence requires all three normalized residuals below `SolveConfig.tolerance`:

....
primal = ||A*x - b||_2 / (1 + ||b||_2)
dual   = ||A^T*lambda + s - c||_2 / (1 + ||c||_2)
gap    = |c^T*x - b^T*lambda| / (1 + |b^T*lambda|)
....

Infeasibility tests `y = lambda/(b^T lambda)` when the denominator is positive:
`A^T y <= infeasibilityTolerance`, `b^T y = 1`. Dual infeasibility tests `z = x/|c^T x|` when
`c^T x < 0`: `||A z||_inf <= infeasibilityTolerance`, `c^T z = -1`, `z >= 0`; unboundedness is
declared only when a primal-feasible point is also known. These floating-point certificate tests
retry on the last completed iterate before raising.

== Newton solver: Cholesky, CG, Auto

[cols="1,2,2",options="header"]
|===
|Strategy |Computation |Driver cost
|`Cholesky` |Aggregate the weighted Gramian and factor its contiguous independent blocks; reuse for both directions. |`O(m^2)` storage; factorization `O(sum(block^3))`, worst case `O(m^3)`.
|`ConjugateGradient` |Apply `v -> A*(W*(A^T*v))+Rd*v` in Spark with a bounded partial-Cholesky preconditioner. |`O(m)` vectors plus `O(m*rank)` preconditioner storage.
|`Auto` |Cholesky through 10000 equality-form rows (or a lower `maxLocalConstraints` cap); CG above it. |Follows the selected strategy.
|===

The 10000-row cutoff is a conservative heuristic, not a universal crossover; the
link:benchmarks.adoc[benchmark methodology] describes how to measure the workload-dependent tradeoff.
`maxLocalConstraints` (default 10000) is a separate resource cap: lowering it can switch Auto
earlier, raising it does not raise the cutoff. To run Cholesky above 10000 rows, select it explicitly
and raise that cap.

Here `m` counts emitted user constraints and upper-bound rows; `n` counts split variables and slacks.
Gramian allocations need roughly `16*m*m` bytes (about 1.6 GB at `m = 10000`) plus ~400 MB executor
aggregation buffers. Explicit Cholesky rejects models above `maxLocalConstraints` and caps packed
arrays at 65535 rows. CG avoids the Gramian limit but keeps row metadata, RHS, residuals and group
keys on the driver with `Int` matrix indices; its matrix-free operator streams each stored row once
per application (dot product, weight, accumulate into a partition sum), and initialization applies a
scalar uniform weight.

== Matrix-free CG equations and regularization

`A` is the original constraint matrix (the code stores `AT`). With `rb = A*x-b`, `rc = A^T*y+s-c` and
`q` the complementarity right-hand side, the CG backend uses primal/dual proximal regularization
following https://webhomes.maths.ed.ac.uk/~jgondzio/reports/mtxFree.pdf[Gondzio, sections 3–6]; both
proximal reference points reset to the current iterate, so `rb`/`rc` stay original-LP residuals with
no fixed offsets.

[source,text]
----
A*dx + Rd*dy = -rb
A^T*dy + ds - Rp*dx = -rc
S*dx + X*ds = q

W = (S/X + Rp)^(-1)
h = rc + q/x
(A*W*A^T + Rd)*dy = -rb - A*W*h
dx = W*(A^T*dy + h)
ds = -rc - A^T*dy + Rp*dx
----

The affine predictor uses `q = -x*s`; the corrector uses `q = -x*s-dxAff*dsAff+sigma*mu`; both share
the operator and preconditioner. Initialization uses `W0 = I/(1+Rp)`, `G0 = A*W0*A^T+Rd`,
`xTilde = W0*A^T*G0^(-1)*b`, `yTilde = G0^(-1)*A*W0*c`, then strictly positive shifts. Cholesky is the
unregularized reference with an inverse-slack cap; its exact zero-separated blocks are factored
independently by the same LAPACK routine, dropping no coupling by tolerance. See
link:benchmarks.adoc[benchmark methodology] for timing and memory interpretation.

`CgConfig` defaults `Rp = Rd = 1e-8` (entries, not square roots), positive throughout a solve. Larger
values improve conditioning but need more outer iterations; very small values lose their effect to
roundoff, so scale the LP before using extreme coefficients. CG weights are `1/(s/x+Rp)` with no
inverse-slack cap; nonpositive, nonfinite or underflowed weights fail explicitly. The regularized CG
operator supports dependent feasible equality rows, while the direct backend requires full row rank.
Retrying with a stronger preconditioner preserves the current solution and cumulative counts without
forming a Gramian.

== Preconditioner and inexact solves

The adaptive preconditioner starts as the regularized diagonal (Jacobi). If an inner solve misses its
tolerance it builds up to 50 partial-Cholesky columns, then doubles the rank on further failures.
Escalation within one weighted system extends the existing factors and Schur diagonal, fetching only
new columns; later outer iterations inherit the rank but rebuild factors for changed weights. Each
pivot is the largest updated Schur-complement diagonal (ties by row index), only that column is
fetched before the next pivot, and the remaining Schur block is approximated by its diagonal, so no
full Gramian is collected.

A pivot at or below `max(Rd, 64*ulp(max(diag(G))))` stops factorization and floors the preconditioner
diagonal; nonfinite values or a Schur diagonal below its negative fail numerically. This guard
affects the preconditioner only; there is no hidden ridge retry after the Newton RHS is built.

The factor budget defaults to 256 MiB (~`32*m*rank` bytes), and a driver work cap also limits rank
via `m*rank^2 <= 2e10`. Explicit `preconditionerRank` is clipped to both; rank 0 selects adaptive
behavior and a zero byte budget forces Jacobi. Sequential pivoting costs one distributed column pass
per pivot, so starting from Jacobi avoids paying for pivots on easy systems.

`cgTolerance` (default `1e-10`) and `cgMaxIterations` control the inner solve; its requested residual
is `max(cgTolerance*norm(rhs), 0.1*tolerance*(1+norm(b)))` (initialization uses only the relative
term), and warm starts reuse the predictor solution for the corrector. After exhausting rank and step
budgets, a finite true residual no larger than `max(target, 1e-3*norm(rhs))` may be returned as an
inexact direction; a larger defect, nonfinite residual or nonpositive curvature raises a numerical
failure unless an original-LP certificate holds on the last completed iterate. The outer primal, dual
and gap residuals are always recomputed from the original LP, so solving only the regularized
equations cannot yield `Optimal`.

Relative to the reference papers, the implementation uses Mehrotra predictor-corrector steps instead
of a fixed barrier reduction, uniform configurable regularization instead of per-entry adjustment,
and Jacobi before partial Cholesky. `CgConfig` tunes the matrix-free backend only; Cholesky ignores
it. Continuous convex quadratic objectives extend these equations below; nonconvex, mixed-integer and
quadratically constrained models are unsupported.

== Convex quadratic objectives

Continuous models support `0.5 * sum(q_i * x_i^2) + c^T x + k` and use only the core runtime
dependencies. Minimization needs each aggregated `q_i >= 0`; maximization needs a concave
(nonpositive-curvature) objective. Build objectives with `QpObjective`
(see link:usage.adoc#_convex_quadratic_objectives[the usage guide]); they add, combine with linear
expressions, and scale, and `setObjective` restores the linear path.

Diagonal curvature specifies curvature, not linear cost, and cannot carry a constant. Repeated terms
sum, missing keys contribute zero, and invalid or duplicate source keys are rejected. Bound shifts
preserve `c' = c + Q*l` and `k' = k + c^T*l + 0.5*l^T Q*l`; fixed variables fold into the constant and
all-fixed objectives are evaluated directly. Curved free variables are rejected because splitting them
introduces coupled curvature; zero-curvature free variables keep the LP behavior. An all-zero-curvature
objective uses the LP path and its restrictions, while an unconstrained nonzero-curvature objective
adds an independent dummy equality to satisfy the initialization contract. Invalid curvature and
nonfinite coefficients raise `LpModelException`. Integer and binary categories and quadratic
constraints are unsupported throughout.

=== Solver equations and optimality

For `0.5*x^T Q*x + c^T*x`, diagonal `Q` changes the Newton weights to `W = (S/X + Q + Rp)^(-1)` and
direction recovery includes `Q*dx`; the diagonal is partitioned with the sparse columns. Stationarity
uses `A^T*lambda + s - c - Q*x`, the primal objective is `0.5*x^T Q*x + c^T*x`, and the dual
expression is `b^T*lambda - 0.5*x^T Q*x`. Convergence requires the primal, stationarity and quadratic
objective-gap tolerances (defaults `1e-8`, with `1e-10` CG inner tolerance); see
https://osqp.org/docs/solver/[OSQP's QP optimality conditions]. A candidate unbounded direction must
also satisfy `Q*d = 0` within tolerance, and classifying unboundedness needs a feasible point. At
degenerate bounds a small objective gap can coexist with larger variable error, so check stationarity
through bound multipliers and complementary products rather than raw gradients.

=== Coupled objectives: sparse factors

Sparse cross-variable terms are supplied as PSD factors `sum_k w_k * (a_k^T x + t_k)^2`, so under the
`0.5*x^T Q*x + c^T*x + k` convention `Q = 2*sum_k w_k*a_k*a_k^T`. Every pair of keys in a factor
produces the matching symmetric cross term; repeated coefficients within a factor sum, and repeated
factors add their penalties. Nonnegative weights prove the PSD structure (including rank deficiency);
negative weights are rejected in a minimization objective, so negate the whole objective for concave
maximization. Arbitrary raw Hessian entries are deliberately not accepted: the caller supplies a PSD
factorization rather than relying on diagonal checks or random probes. No dense Hessian or explicit
inverse is formed.

Per factor, compilation introduces `u, v >= 0`, the equality `a^T*x+t = u-v`, and the diagonal
penalty `w*(u^2+v^2)`. For a fixed residual the minimum sets one of `u,v` to zero and equals
`w*(a^T*x+t)^2` -- an exact convex reduction whose lifted stationarity equations recover the original
gradient through the factor-row multipliers. The reduction adds two columns and one row per factor and
applies the weighted normal operator to the enlarged sparse matrix; CG solves a positive-definite
regularized normal system and is never applied to the indefinite KKT matrix directly. Cholesky storage
is quadratic in the enlarged row count, while CG keeps distributed sparse columns and bounded
preconditioner storage. Because free-variable splitting can make the coupled Cholesky system singular
near convergence, `Auto` selects regularized CG for coupled models with free variables and explicit
Cholesky is rejected.

Factor lifting supports free, shifted and fixed original variables, and the auxiliary variables are
created per compilation without mutating the user problem: diagnostics expose `__qp_factor_*` rows (a
reserved prefix), internal snapshots include the auxiliary columns, and `value`/`values` reconstruct
the user variables in original units. Replacing an objective or solving repeatedly does not accumulate
variables or constraints. Use separable objectives for diagonal Hessians; sparse factors add cross
terms and a structural convexity contract, not a performance advantage over the diagonal path. The
link:benchmarks.adoc[benchmark methodology] defines the analytic QP comparison and accuracy checks.

== Verifying solve evidence

Continuous solve results expose `solution.evidence: Option[LpEvidence]`; `None` means evidence is
unavailable, including optimal, stopped and integer solves. Presolve validation errors (contradictory
declared bounds, inconsistent duplicate equalities, impossible constant rows) raise exceptions instead
of returning a result. `LpEvidenceVerifier` recomputes every condition against the materialised
original-model snapshot -- including eliminated variables and rows -- checking missing or duplicate
keys, nonfinite values, signs, stationarity, feasibility and normalization without trusting solver
status or internal residuals. Residuals use absolute original units, so large scales or cancellation
can fail a tight tolerance even for a correctly classified result; these are numerical witnesses, not
exact-arithmetic proofs, and the caller chooses the tolerance. `solution.close()` releases the
snapshots, so finish Spark actions first. No IIS or MIP proof is implied.

=== Infeasibility certificate

`InfeasibilityCertificate` exposes original row multipliers (with names and group labels) and
distributed bound multipliers keyed by `(setIndex, encodedKey) -> (lower, upper)`; `model.variables`
carries display names, declared bounds and the original sparse coefficients, and fixed variables are
retained. Merged or presolved rows have zero multipliers, rows are never rescaled (multipliers keep
original row units), bound shifts change only the right-hand side, and free-variable splits are
recombined. The sign convention is `A^T y + lower + upper = 0` with `b^T y + l^T lower + u^T upper = 1`:
a `<=` or upper-bound multiplier is nonpositive, a `>=` or lower-bound multiplier is nonnegative,
equality multipliers are unrestricted, and absent-bound multipliers must be zero.

=== Unbounded direction

`UnboundedDirection` exposes an original-unit direction and, when the solver proved primal
feasibility, a point. The direction is zero on fixed variables, omits bound shifts, normalizes its
objective improvement to one in the model's objective sense, and obeys homogeneous row and bound
recession conditions. Without a point, `verify` returns `valid=false`, because a direction alone
cannot separate infeasibility from unboundedness; to verify a separately obtained original-model point
use `proof.copy(point = Some(values))`.

=== Quadratic models

The snapshot keeps the original unshifted linear cost and diagonal curvature, and a recession
direction must additionally satisfy `Q*d = 0`. Coupled objectives expose the factor-expanded model
with its named auxiliary rows and variables; verifying that equivalent formulation certifies the
original problem after projection onto the user variables. These auxiliary fields are explicit, never
silently discarded.

== Opt-in progress policy

When stagnation detection is enabled, `StagnationConfig` adds separate outer and inner progress
windows (defaults: 10 outer iterations patience, absolute improvement `1e-10` plus relative `1e-3`, 100
inner steps patience, 2000-step inner cap). Outer progress compares original-model violation and the
primal/dual/gap residuals before a feasible candidate appears, then objective improvement or improving
residuals afterward, each component using `absoluteImprovement + relativeImprovement * abs(best)`.
Inner progress compares `norm(rhs-G*dy)/norm(rhs)` on true residuals across restarts and rank changes
for one right-hand side; a stalled or capped inner solve requests `NoProgress` and discards its
unfinished direction. With controls disabled, inner solves fall back to the per-rank numerical
recovery and inexact-acceptance policy.

See link:usage.adoc#_progress_and_cooperative_stopping_continuous_models[progress usage] for
callbacks, metric groups, cancellation and candidate ownership.

== Integer and binary models

Branch-and-bound compiles once and reuses `AT` and `c`; tighter integer bounds change only the RHS and
objective offset. Optional cuts append rows and slack columns for a node. Integer bounds, cut domains
and integral column coefficients stay on the driver.

[mermaid]
----
flowchart TD
  Q[Take node with smallest lower bound] --> B{Bound prunes node?}
  B -->|Yes| N[Next node]
  B -->|No| L[Solve LP relaxation]
  L --> I{Feasible integral point?}
  I -->|Yes| C[Check rounding and update incumbent]
  I -->|No| F[Branch on fractional variable or split interval]
  C --> N
  F --> N
  N --> E{Queue empty or node limit?}
  E -->|No| Q
  E -->|Yes| R[Report incumbent and search status]
----

For minimization the relaxation's dual objective is the node lower bound and its primal objective a
candidate upper bound. A branch is discarded on contradictory row bounds or an infeasibility
certificate. A fractional value `v` splits into `x <= floor(v)` and `x >= floor(v)+1`; near-integer
candidates are rounded only after checking the constraint residual, and the objective includes the
rounding change. Exhausting the search proves optimality within `mip.gapTolerance`, while unresolved
branches or `mip.maxNodes` exhaustion give `IterationLimit`. Defaults are 1000 LP nodes, integrality
tolerance `1e-6` and relative gap tolerance `1e-9`.

Example: maximizing integer `x+y` with `2*x+2*y <= 3` relaxes to `1.5`, and branching finds the
integer optimum `1`. The default search processes one node at a time. Optional bounded parallel search solves
multiple node relaxations, with one driver coordinator managing the tree and incumbent.
Search can grow exponentially; distributed LP operations do not make arbitrary large
integer searches inexpensive.

== Cutting planes, strong branching and parallel search

`MipConfig.search` controls three independently optional capabilities. The default retains best-first node selection, most-fractional branching, no cuts and one node relaxation at a time. This baseline has deterministic branching and tie handling for a fixed compiled model; floating-point reductions and Spark input order can still affect numerical results.

The cut family is binary knapsack covers. A compiled equality gives a necessary knapsack inequality when nonintegral nonnegative columns cannot decrease its activity. Negative bounded integer contributions are bounded conservatively. Positive coefficients of integral columns with unit-width root and node intervals are eligible for a cover. If their weights exceed the conservatively expanded capacity, at most `|cover|-1` of those shifted binary variables can be one. Greedy separation favors high relaxation values and removes redundant members. Cuts must be violated by the current relaxation. General integer variables can contribute to the capacity bound but are not converted to binary variables implicitly. Gomory, MIR and lifted-cover families are not implemented.

Weight and capacity arithmetic uses exact decimal representations of the input binary doubles. A scale-dependent positive allowance, finite-coefficient checks and a coefficient-ratio limit reject numerically marginal deductions. Root cuts are globally valid. A cut generated below the root records that node's full integral bound domain and is inherited only by descendants within it; it is never promoted to siblings. Duplicate cuts and round/per-node/whole-search budgets limit separation. Appended cut slacks are removed when converting the LP result back to the original compiled coordinates. Automatic Newton selection uses regularized CG for augmented cut systems. Every incumbent is checked against the original constraints and SOS groups.

Strong branching probes both children of a bounded set of fractional candidates. Per-probe iteration and whole-search probe limits bound extra LP work. A finite, converged dual bound can strengthen the child's inherited bound; an incomplete or numerically unsuccessful probe retains the valid parent bound. Contradictory row bounds or an LP infeasibility certificate can discard a probed child. The branching score weights the smaller improvement by ten and adds the larger improvement. Probe iterates do not become incumbents. Probes and cut re-solves count as relaxations and iterations, separately from processed search nodes.

Parallel search uses a fixed worker pool and a single coordinator. Launched nodes reserve the node budget; queued and in-flight nodes both contribute to the global bound until resolved. The coordinator alone updates the incumbent, cut/probe budgets, tree and original-unit gap. It processes completed relaxations and performs their cut re-solves and probes while at most `parallelNodes-1` other nodes remain active, so total concurrent LP work stays bounded. Completion order can change the search tree, tie choices, node count and time. One worker retains the reproducible baseline mode.

Cancellation and deadlines use the same cooperative LP stop checks as serial search. Started workers drain before resources are released; accepted incumbents and unresolved-node bounds are retained. No bound is inferred from an incomplete iterate. Callback exceptions trigger worker draining and cleanup before propagation. A deadline is not a hard wall-clock return guarantee: Spark actions already in progress must complete or reach a solver stop check. All user callbacks run on the coordinating driver thread. Worker iteration diagnostics use a bounded queue that can coalesce older events; incumbent and global-bound updates are never discarded through that queue.

The preflight parallel memory budget estimates concurrent driver Newton storage: `16*m*m + 128*m` bytes for Cholesky and `128*m + cgConfig.preconditionerMemoryBytes` for CG, taking the larger estimate for the uncut system and the maximum permitted cut-row count. This includes the uncut Cholesky path even when augmented systems use CG. `MipSummary.search.estimatedPeakLocalBytes` reports the corresponding estimate for concurrently active relaxations. This is not a total process or executor memory cap. Distributed augmented matrices, checkpointed candidates, Spark caches/shuffles, integral-column/cut-domain metadata and baseline JVM storage need additional memory. Each active LP submits Spark jobs; Spark scheduling and available executor cores determine whether those jobs execute concurrently. See the usage guide for controls and link:benchmarks.adoc[benchmark methodology] for comparison scope.

Knapsack covers and branch-and-bound follow the standard methods in https://onlinelibrary.wiley.com/doi/book/10.1002/9781118627372[Integer and Combinatorial Optimization] and the https://onlinelibrary.wiley.com/doi/abs/10.1002/9780470400531.eorms0204[Knapsack Cover Inequalities] reference. https://scipopt.org/doc/html/branch__fullstrong_8c.php[SCIP's full strong branching documentation] describes the established branching technique; Spark LP uses its own bounded probing policy and does not embed SCIP.
