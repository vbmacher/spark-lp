= How spark-lp solves a model
:toc: left
:source-highlighter: highlightjs

== Compile to equality form

The continuous solver minimizes `c^T x` subject to `A x = b`, `x >= 0`.
The compiler stores columns of `A` as sparse Spark rows of `AT = A^T`.
Variable order is `(declaration order, encoded key)`; row order follows constraint
declaration and group keys. No wide DataFrame pivot is needed.

[mermaid]
----
flowchart LR
  M[Model and Spark sources] --> V[Validate keys and coefficients]
  V --> P[Fold fixed variables and shift bounds]
  P --> E[Check empty rows and exact duplicate equalities]
  E --> A[Add inequality and upper-bound slacks]
  A --> C[Build aligned sparse AT and cost blocks]
  C --> L[Continuous LP or integer search]
  L --> R[Undo transformations and report diagnostics]
----

[cols="1,2",options="header"]
|===
|User model |Solver representation
|`x >= l` |`x = l + y`, `y >= 0`; subtract `a*l` from RHS and add `c*l` to objective constant.
|`x <= u`, with finite `l` |Add `y + slack = u - l`.
|`x = l = u` |Remove the variable and substitute its value.
|Free `x` |`x = positive - negative`, both nonnegative.
|`a*x <= b` / `a*x >= b` |Add `+slack` / `-slack` to obtain equality.
|Maximize |Negate costs; restore the objective sign and constant afterward.
|===

For example, minimize `2*x + 7` with `5 <= x <= 10` becomes minimize `2*y + 17`
with `y + slack = 5`. The optimum `y = 0` reconstructs `x = 5`, cost `17`.
Duplicate detection uses hashes to find candidates, then compares normalized coefficients
before merging. Distinct rows are never merged solely because their hashes match.

== Predictor and corrector

`x` is the primal vector, `lambda` the equality multiplier, and `s` the nonnegative dual slack.
Initialization solves two unweighted normal systems, then shifts `x` and `s` strictly positive.
A zero complementarity starting estimate receives a positive shift, including zero-cost models.

[mermaid]
----
flowchart TD
  I[Initialize positive x and s] --> R[Compute primal and dual residuals]
  R --> W[Update mu and diagonal weights]
  W --> P[Solve affine predictor]
  P --> C[Choose centering and solve corrector]
  C --> U[Step while keeping x and s positive]
  U --> T{Residuals below tolerance?}
  T -->|Yes| O[Optimal]
  T -->|No| F{Infeasibility certificate?}
  F -->|Yes| S[Report certificate status]
  F -->|No| B{Iteration budget left?}
  B -->|Yes| R
  B -->|No| L[IterationLimit]
----

At each iteration, `mu = x^T s / n` and `D2 = diag(x/s)` with guarded inverses.
Both Newton directions solve the same system `A D2 A^T deltaLambda = rhs`.
The affine predictor estimates progress toward the boundary. Its predicted complementarity
sets `sigma = min(1, (muAffine/mu)^3)`; the corrector adds centering and the predictor's
second-order correction. The step uses `etaIteration` to stay inside the nonnegative cone.
`mu` is recomputed from the current iterate every time.
This follows the predictor/corrector formulation in
https://link.springer.com/article/10.1007/s10589-019-00103-y[Cui et al., section 2.1].

Convergence requires all three normalized residuals below `SolveConfig.tolerance`:

....
primal = ||A*x - b||_2 / (1 + ||b||_2)
dual   = ||A^T*lambda + s - c||_2 / (1 + ||c||_2)
gap    = |c^T*x - b^T*lambda| / (1 + |b^T*lambda|)
....

For infeasibility, test `y = lambda/(b^T lambda)` when the denominator is positive:
`A^T y <= infeasibilityTolerance`, `b^T y = 1`.
For dual infeasibility, test `z = x/|c^T x|` when `c^T x < 0`:
`||A z||_inf <= infeasibilityTolerance`, `c^T z = -1`, `z >= 0`.
The latter means unboundedness only when a primal-feasible point is also known.
These are floating-point certificate tests, governed by the configured tolerance.
A numerical failure retries those tests on the last completed iterate before raising an exception.

== Choose the Newton solver

[cols="1,2,2",options="header"]
|===
|Strategy |Computation |Driver cost
|`Cholesky` |Aggregate and factor the weighted Gramian once per outer iteration; reuse for both directions. |`O(m^2)` storage and `O(m^3)` factorization.
|`ConjugateGradient` |Apply `v -> A*(W*(A^T*v))+Rd*v` in Spark; use a bounded partial-Cholesky preconditioner. |`O(m)` iteration vectors plus `O(m*rank)` preconditioner storage.
|`Auto` |Cholesky through 1000 equality-form rows (or a lower `maxLocalConstraints` cap); CG above it. |Follows the selected strategy.
|===

The shared core/DSL cutoff comes from the equal-accuracy runs in
link:../benchmarks/README.md[the reproducible benchmark report]: results were mixed at
1000 rows, while CG won from 1500 onward in the measured workloads. This is a conservative
measured default for the recorded local environment, not a universal performance bound.
`maxLocalConstraints` remains a separate resource cap (default 5000): lowering it can
switch Auto earlier; raising it does not raise the performance cutoff. To use Cholesky
above 1000 rows, select it explicitly and allow enough rows with that resource cap.

Here `m` includes emitted user constraints and upper-bound rows; `n` includes split
variables and slacks. Allow roughly `16*m*m` bytes for Gramian-related allocations:
about 400 MB at `m = 5000`, excluding other driver data. Explicit Cholesky rejects
models above `maxLocalConstraints` and has a packed-array limit of 65535 rows.
CG avoids that Gramian limit, but row metadata, RHS, residuals, and group keys remain on
the driver; matrix indices are still `Int`. Each CG step adds distributed work.

=== Regularized matrix-free LP equations

For the equations below, `A` is the original constraint matrix (the code stores `AT`).
Let `rb = A*x-b`, `rc = A^T*y+s-c`, and `q` be the complementarity right-hand side.
The CG backend implements primal and dual proximal regularization following
https://webhomes.maths.ed.ac.uk/~jgondzio/reports/mtxFree.pdf[Gondzio, sections 3–6].
Both proximal reference points are reset to the current iterate. Thus `rb` and `rc`
are residuals of the original LP; there are no fixed-reference offsets to add.

[source,text]
----
A*dx + Rd*dy = -rb
A^T*dy + ds - Rp*dx = -rc
S*dx + X*ds = q

W = (S/X + Rp)^(-1)
h = rc + q/x
(A*W*A^T + Rd)*dy = -rb - A*W*h
dx = W*(A^T*dy + h)
ds = -rc - A^T*dy + Rp*dx
----

The affine predictor uses `q = -x*s`; the corrector uses
`q = -x*s-dxAff*dsAff+sigma*mu`. Both share the same operator and preconditioner.
Initialization applies the regularized least-squares inverse with `W0 = I/(1+Rp)`:
`G0 = A*W0*A^T+Rd`, `xTilde = W0*A^T*G0^(-1)*b`, and
`yTilde = G0^(-1)*A*W0*c`, followed by the existing strictly positive shifts.
Cholesky remains the unregularized reference, including its historical inverse-slack cap.

`MatrixFreeConfig` supplies constant scalar diagonal entries `Rp = 1e-8` and
`Rd = 1e-8` by default. These are entries, not their square roots. They stay positive
throughout a solve. Larger values can improve conditioning but require more outer
iterations; very small values can lose their effect to roundoff. Scale the LP before
using extreme coefficients. CG weights use `1/(s/x+Rp)` without the legacy inverse-slack
cap (`epsilon`/`valueCap`); nonpositive, nonfinite or underflowed weights fail explicitly.
Dependent feasible equality rows are supported by CG's regularized operator; the direct
backend still requires full row rank.

=== Preconditioner and inexact solves

The adaptive preconditioner starts with the regularized diagonal (Jacobi). If an inner
solve misses its requested tolerance, it builds up to 50 partial-Cholesky columns, then
doubles the rank on further failures. Escalation carries forward to later outer iterations.
Each pivot is the largest *updated Schur-complement diagonal*, with ties broken by row
index. Only that column is fetched from Spark before the next pivot is chosen. The
remaining Schur block is approximated by its diagonal. No full Gramian is collected.

A pivot at or below `max(Rd, 64*ulp(max(diag(G))))` stops factorization. The remaining
preconditioner diagonal is floored at that value; nonfinite values or a Schur diagonal
below its negative fail numerically. This roundoff guard affects the preconditioner only:
there is no hidden ridge retry that changes the Newton operator after building its RHS.

The factor budget defaults to 256 MiB, conservatively allowing `32*m*rank` bytes;
`O(m)` vectors, RDD storage and Spark runtime overhead are separate. A driver work cap
also limits rank using `m*rank^2 <= 2e10`. Explicit `preconditionerRank` is clipped to
these same caps. Rank 0 selects adaptive behavior; a zero byte budget forces Jacobi.
Sequential pivoting costs one distributed column pass per selected pivot, so beginning
with Jacobi avoids paying for unnecessary pivots on easy systems.

`cgTolerance` (default `1e-10`) and `cgMaxIterations` control the inner solve. Its requested
residual norm is `max(cgTolerance*norm(rhs), 0.1*tolerance*(1+norm(b)))`; initialization
uses only the relative term. True residual replacement checks `rhs-G*dy`, including `Rd`.
Warm starts reuse the predictor solution for the corrector. After exhausting the rank
and step budgets, a finite true residual no larger than `max(target, 1e-3*norm(rhs))`
may be returned as an inexact direction. A larger defect, nonfinite residual or
nonpositive curvature raises a numerical failure, unless an original-LP certificate
can be established on the last completed iterate. Inner iterations are counted across
restarts and rank escalations.

The outer primal, dual and objective-gap residuals are always recomputed from the
original LP. Solving only the regularized equations cannot yield `Optimal`.
The implementation deliberately retains Mehrotra predictor-corrector steps instead of
the paper's fixed barrier reduction, uses uniform configurable regularization instead
of dynamically adjusting individual diagonal entries, and starts with Jacobi before
partial Cholesky. General quadratic programming is outside this implementation.

[source,scala]
----
import com.github.vbmacher.spark_lp.MatrixFreeConfig

val config = SolveConfig(
  newtonSolver = NewtonSolver.ConjugateGradient,
  cgTolerance = 1e-10,
  cgMaxIterations = 1000,
  matrixFree = MatrixFreeConfig(
    primalRegularization = 1e-8,
    dualRegularization = 1e-8,
    preconditionerRank = 50,
    preconditionerMemoryBytes = 128L * 1024 * 1024))
----

== Integer and binary models

Compile once. Branch-and-bound reuses `AT` and `c`; tighter integer bounds change the RHS
and objective offset. Integer bounds and column coefficients are held on the driver.

[mermaid]
----
flowchart TD
  Q[Take node with smallest lower bound] --> B{Bound prunes node?}
  B -->|Yes| N[Next node]
  B -->|No| L[Solve LP relaxation]
  L --> I{Feasible integral point?}
  I -->|Yes| C[Check rounding and update incumbent]
  I -->|No| F[Branch on fractional variable or split interval]
  C --> N
  F --> N
  N --> E{Queue empty or node limit?}
  E -->|No| Q
  E -->|Yes| R[Report incumbent and search status]
----

For minimization, use the relaxation's dual objective as its lower bound; the primal
objective is a candidate upper bound. Discard a branch whose row bounds are contradictory
or whose LP has an infeasibility certificate. A fractional value `v` splits into
`x <= floor(v)` and `x >= floor(v)+1`. Near-integer candidates are rounded only after
checking the resulting constraint residual; the objective includes the rounding change.

Example: maximize integer `x+y` with `2*x+2*y <= 3`. The relaxation reaches `1.5`;
branching finds an integer optimum of `1`. Exhausting the search proves optimality within
`mip.gapTolerance`; unresolved branches or `mip.maxNodes` exhaustion give `IterationLimit`.
Defaults: 1000 LP nodes, integrality tolerance `1e-6`, relative gap tolerance `1e-9`.
Search is sequential on the driver and can grow exponentially; distributed LP operations
do not make arbitrary large integer searches inexpensive.
